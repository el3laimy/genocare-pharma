# Software Requirements Specification — GenoCare

## 1. الحالة والحدود

ما يلي متطلبات مؤكدة من وصف النشاط ما لم يوسم صراحة بأنه توصية أو قرار معلق. النظام تطبيق Windows محلي، مستخدم واحد حاليًا، يعمل دون اتصال.

## 2. المتطلبات الوظيفية

### الأصناف والمخزون

1. لكل صنف كود داخلي فريد، اسم، ووحدة بيع هي العلبة فقط.
2. يسجل النظام سعر الجمهور وسعر الشراء يدويًا، ويحتفظ بسعر كل سطر في المستند المرحل.
3. يسجل Batch لكل صنف مع تاريخ الصلاحية والكمية والحركات المرتبطة به.
4. يقترح النظام التشغيلة الأقرب انتهاءً عند البيع، ويسمح للمستخدم بتعديل الاختيار مع تسجيله.
5. يصدر تنبيهًا للتشغيلات التي تبقى على انتهائها ثلاثة أشهر، وتنبيه نقص مبنيًا على حركة المبيعات.
6. يدعم الجرد والتسويات مع سبب ومرجع وسجل تدقيق.

### المشتريات والاستلام

1. تسجيل المورد وأمر/فاتورة شراء واستلام على دفعات.
2. كل استلام يحدد التشغيلة وتاريخ الصلاحية والكمية والتكلفة.
3. يدعم الرصيد الافتتاحي للمورد والمديونية الناتجة عن المشتريات.

### المبيعات والطلبات

1. تسجيل طلب العميل وتحويله إلى فاتورة مع حفظ العلاقة.
2. بيع العلبة فقط، وخصم متغير لكل فاتورة.
3. دعم سطور Bonus منفصلة بحيث يمكن تمييز الكمية المجانية عن الكمية المفوترة.
4. منع ترحيل فاتورة تتجاوز المخزون المتاح وفق السياسة التي سيؤكدها العميل.
5. تسجيل العميل، مندوب التسليم، حالة التسليم، والتحصيل.

### الحسابات والتحصيل

1. تسجيل العملاء والموردين والحد الائتماني ومدة السداد.
2. دعم أرصدة افتتاحية.
3. تسجيل التحصيل وتطبيقه على إجمالي رصيد العميل، مع كشف حساب قابل للطباعة.

### المرتجعات والتدقيق والتشغيل

1. مرتجع مرتبط بالفاتورة الأصلية، ومرتجع استثنائي بسبب ومرجع.
2. طباعة فواتير A4 وكشوف الحساب.
3. سجل تدقيق لجميع الإضافات والتعديلات والترحيل والعكس والاستيراد.
4. نسخ احتياطي محلي وخارجي، وسحابي عند توفر الإنترنت.
5. استيراد الأصناف والأرصدة والتشغيلات والمديونيات من Excel مع معاينة وأخطاء قابلة للتنزيل.

## 3. المتطلبات غير الوظيفية

- **الدقة:** العمليات المالية ذرية، قابلة للعكس، ولا تعدل مستندًا مرحلًا بصمت.
- **الأداء:** فتح الشاشات الأساسية وعمليات البحث ملائم لحجم 500 صنف و100 فاتورة يوميًا؛ معيار القياس التفصيلي معلق.
- **المحلية:** واجهة RTL عربية، تنسيق تاريخ/عملة قابل للإعداد.
- **الاعتمادية:** SQLite محلية، معاملات ACID، وفحص سلامة النسخ الاحتياطية.
- **الأمان:** أقل صلاحية، قفل جلسة اختياري مستقبلًا، وعدم تسجيل أسرار في Audit Log.
- **القابلية للصيانة:** وحدات مستقلة واختبارات مجال وخدمات، دون اعتماد واجهة WinUI على قاعدة البيانات.
- **التوسع:** نموذج بيانات يدعم مستخدمين وأجهزة لاحقًا دون تنفيذ مزامنة في الإصدار الأول.

## 4. معايير قبول أولية

| العملية | معيار قابل للاختبار |
|---|---|
| بيع | ترحيل فاتورة ينقص Batch المحدد، يحفظ سعر وخصم السطر، ويحدث الرصيد والحساب معًا. |
| FEFO | عند وجود Batchين صالحين، يقترح النظام الأقرب انتهاءً ويقبل تغيير المستخدم ويسجل الاختيار. |
| شراء جزئي | استلامان لنفس الشراء يضيفان كميات وتشغيلات منفصلة ولا يثبتان غير المستلم. |
| تحصيل | تسجيل تحصيل يخفض الرصيد الإجمالي ويظهر في كشف الحساب دون تغيير قيمة الفاتورة. |
| مرتجع | المرتجع المرتبط لا يتجاوز الكمية القابلة للإرجاع؛ الاستثنائي يتطلب سببًا وموافقة/سياسة يحددها العميل. |
| تدقيق | تعديل مؤثر يعرض المستخدم والوقت والقيم قبل/بعد والمرجع. |
| نسخ احتياطي | يمكن إنشاء نسخة واستعادتها في بيئة اختبار مع تحقق سلامة البيانات. |

## 5. ما لم يدخل الإصدار الأول

المزامنة متعددة الأجهزة، تطبيق الهاتف، التكامل مع ERP أو شركات الشحن، وتكامل الدفع الإلكتروني؛ كلها قرارات/مراحل لاحقة.
