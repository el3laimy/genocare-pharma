# نموذج المجال

## الكيانات الأساسية

| الكيان | المسؤولية |
|---|---|
| Product | الصنف والكود والوحدة والأسعار الحالية والحالة. |
| Batch | تشغيلة لصنف، رقمها/صلاحيتها وكمياتها. |
| StockMovement | دخول/خروج/تسوية مرجعها ومستندها وBatchها. |
| Customer / Supplier | الطرف، بيانات الاتصال، الرصيد الافتتاحي، الائتمان ومدة السداد. |
| SalesOrder | طلب عميل قبل الترحيل. |
| SalesInvoice / SalesLine / BatchAllocation | فاتورة ولقطة السعر/الخصم وبند قد يوزع كميته على عدة Batches. |
| Purchase / PurchaseReceipt | شراء واستلام كلي/جزئي مع Batch وتكلفة. |
| Payment | تحصيل عميل أو سداد مورد وتطبيقه على الحساب. |
| Return / ReturnLine | مرتجع مرتبط أو استثنائي مع السبب. |
| Stocktake / Adjustment | جرد وفروق وتسويات مع اعتماد. |
| Representative / Delivery | مندوب وحالة تسليم وتحصيل. |
| AuditEntry | من، متى، ماذا، قبل/بعد، والمرجع. |

## أساس الكتالوج والمخزون (Task 003)

- `Product` يفرض كودًا داخليًا واسمًا عربيًا وسعرين حاليين غير سالبين، ويثبت وحدة البيع `Box`. السعر الحالي مرجعي ولا يمثل تكلفة حركة تاريخية، ولا توجد خصومات في طبقة المجال هذه.
- `Batch` له هوية غير قابلة للتغيير، ويرتبط بـProduct ورقم Batch وتاريخ صلاحية. لا يحمل رصيدًا مستقلًا؛ الرصيد مشتق من الحركات.
- `StockMovement` مجرد سجل مصدره واضح (`Receipt`, `OpeningStock`, `Issue`, `Adjustment`) ويرتبط بـProduct وBatch وكمية صناديق صحيحة موجبة. التسوية تستخدم اتجاه زيادة/نقص بدل كمية سالبة.
- `StockCondition` يميز `Available` و`Quarantined` و`Damaged`. `SaleableQuantity` يحسب من Available فقط، ولا تدخل الحالات الأخرى في FEFO.
- `InventoryStatusTransition` يمثل نقلًا ذريًا منطقيًا: يولد حركة نقص من الحالة المصدر وحركة زيادة للحالة الهدف بنفس المرجع، ويرفض الحالة نفسها والكمية الافتراضية/غير الصالحة. تنفيذ المعاملتين ذريًا مسؤولية طبقة التطبيق/التخزين لاحقًا.
- `FefoAllocator` خدمة مجال نقية تقترح التخصيص حسب أقرب صلاحية، ثم رقم Batch ثم الهوية عند تعادل الصلاحية. ترفض تكرار Batch أو خلط Products؛ على المستهلك تزويدها بالتشغيلات المؤهلة وفق سياسة الصلاحية التي لم تعتمد بعد. يمكن للمستهلك تعديل الاقتراح لاحقًا؛ الخدمة لا تطبق تجاوزًا إداريًا أو بيعًا منتهيًا أو رصيدًا سالبًا.

في Infrastructure تتحول الانتقالات إلى سجلين مرتبطين بـTransactionId واحد وEntryIndex مختلف. إعادة نشر TransactionId مرفوضة، وفحص المصدر والحفظ يتمان داخل SQLite transaction واحدة. هذه آلية تخزين وليست اعتمادًا لسياسة التجاوز أو بيع المنتهي.

## نمذجة البيع والمخزون التفصيلية

- `SalesInvoiceLine` يحفظ `RetailPriceSnapshot` و`DiscountPercent` و`NetUnitPrice`، ولا يرتبط بتشغيلة واحدة.
- `BatchAllocation` يربط سطر الفاتورة بـBatch واحد أو أكثر؛ مجموع الكميات المخصصة يساوي الكمية المباعة، و`BonusQuantity` حقل مستقل لكنه يخصم من المخزون مع الكمية المدفوعة وفق سياسة البونص.
- المخزون يفصل `AvailableQuantity` عن `QuarantineQuantity` و`NonSellableQuantity`؛ لا تدخل الكميات غير الصالحة في اقتراح FEFO.
- نقص المخزون لا ينشئ رصيدًا سالبًا ضمنيًا. تجاوز إداري، إن اعتمد، يولد `StockOverride/Adjustment` بسبب وصلاحية ومرجع Audit.
- تكلفة المبيعات الفعلية تأتي من Batch allocations (مثل moving/lot cost) وتبقى مستقلة عن سعر الشراء الحالي في `Product`.
- الاستلام الجزئي يزيد المخزون عند كل Receipt، بينما مديونية المورد تسجل على Purchase/الفاتورة مرة واحدة؛ لا تنشئ كل دفعة استلام مديونية مكررة.
- تعديل فاتورة محفوظة يتم عبر نسخة/عكس/Adjustment مضبوط حسب القرار، وليس UPDATE صامتًا لصف مرحّل.

## علاقات وقواعد مؤكدة

- Product له Batches عديدة؛ كل حركة مخزون تشير إلى Product وBatch.
- SalesInvoice لها SalesLines، ويمكن أن ترتبط بـ SalesOrder وCustomer وRepresentative.
- PurchaseReceipt يتبع Purchase وقد يحتوي Batches متعددة، والاستلام الجزئي لا يثبت الكمية غير المستلمة.
- Return المرتبط يشير إلى SalesInvoice الأصلية؛ الاستثنائي يحتاج سببًا وسياسته معلقة.
- Payment يزيد/ينقص حساب الطرف ويظهر في كشفه؛ لا يغير إجمالي الفاتورة.
- السعر والخصم والضريبة إن وجدت snapshot داخل السطر وقت الترحيل.
- الكمية المباعة بالعلبة؛ Bonus يظل معلومًا ولا يخلط تلقائيًا مع الكمية المفوترة.
- FEFO اقتراح تشغيلي: الصلاحية الأقدم أولًا، مع السماح بتجاوز الاقتراح وتسجيل السبب/المستخدم حسب القرار.
- لا يسمح بالمخزون السالب إلا إذا أكد العميل سياسة صريحة.

## حالات المستند المقترحة

`Draft → Posted → Reversed/Cancelled`، مع منع تعديل المستند المرحل مباشرة. الأسماء وقواعد الإلغاء النهائية ضمن القرارات المفتوحة.

## Value Objects وتوابع

Money، Quantity، DateRange، PartyAccount، DocumentNumber، ExpiryDate. خدمة `BalanceCalculator` تحسب الرصيد من الحركات، وخدمة `FefoAllocator` تقترح Batches، وخدمة `CreditPolicy` تتحقق من الحد/الأجل.

## غير محسوم

الضرائب، العملة، سياسة الكميات السالبة، شكل رقم المستند، قواعد تجاوز الصلاحية، اعتماد التسويات، وطريقة تطبيق الدفعة على فواتير متعددة.
